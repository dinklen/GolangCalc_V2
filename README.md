## О проекте
Данный проект предоставляет API калькулятора, производящего параллельные вычисления на микросервисе и поддерживающего аутентификацию пользователей.

---
## Особенности
### Параллельность вычислений
Пользователь отправляет выражение на сервер по соответствующему API. Выражение делиться на подвыражения, и вычисляет параллельно возможные на тот момент подвыражения.

### Поддержка аутентификации
Имеется возможность создать учётную запись, к которой будут привязаны дальнейшие отправляемые от неё математические выражения.

### Сохранение истории подвыражений
Каждые отправленные выражения и их подвыражения сохраняются в базе данных, которые в любой момент можно получить.

## Установка и запуск
Давайте клонируем репозиторий:
```bash
git clone https://github.com/dinklen/GolangCalc_V2.git
```

Теперь нужно поставить все зависимости.
> дорогой Docker...

Нужно:

### Redis
#### Установка для Linux/Ubuntu
Откройте терминал и введите следующие команды:
```bash
sudo apt update
sudo apt install redis-server
```
Redis установлен. Теперь нужно запустить сервер
```bash
sudo systemctl start redis
```
Для остановки этой службы замените `start` на `stop`.

#### Установка для MacOS
Установите его через Homebrew:
```bash
brew install redis
```

И затем запустите его:
```bash
brew services start redis
```

#### Установка для Windows
> **note**: во избежание проблем, установите WSL:
  ```powershell
  wsl --install
  ```

Далее вводите команды в нём, описанные в разделе для *Linux/Ubuntu*.

### PostgreSQL
#### Установка для Linux/Ubuntu и Windows (WSL)
Скачайте его:
```bash
sudo apt update
sudo apt install postgresql postgresql-contrib
```
А затем запустите его службу:
```bash
sudo systemctl start postgresql
```

#### Установка для MacOS
Установка:
```bash
brew install postgresql
```
И запуск:
```bash
brew services start postgresql
```

#### Создание пользователя и БД в PostgreSQL
Перейдите в PostgreSQL:
```bash
psql postgres
```
Создайте пользователя с желанным паролем и именем *(не забудьте изменить значения в `GolangCalc_V2/internal/config/config.yaml` в полях `database.password` и `database.user` на соответствующие)*:
```sql
CREATE USER <имя> WITH PASSWORD '<пароль>';
CREATE DATABASE calc_database OWNER myuser;
\q
```

С остальным справятся миграции.

## Отправка запросов на сервер
Стоит оговорится об эндпоинтах.

| Эндпоинт | Метод | Описание | Значения | JWT Auth |
| :------: | :---: | :------: | :--: | :---: |
| `/register` | `POST` | Регистрации новой учётной записи. | `login`<br>`password` | `none` |
| `/login` | `POST` | Вход в учётную запись. | `login`<br>`password` | `none` |
`/refresh` | `POST` | Обновление access и refresh токенов | `refresh_token` | `none` |
`/logout` | `POST` | Отзыв access токена (фактический выход из аккаунта). | `access_token` | `none` |
`/api/v1/calculate` | `POST` | Принятие выражения для вычисления. | `expression` | `checking` |
| `/api/v1/expression` | `GET` | Получение истории выражений в контексте конкретного пользователя. | `none` | `checking` |
| `/api/v1/expression/<id>` | `GET` | Получение конкретного выражение из базы данных. | `none` | `checking` |

В этой таблице перечислены все эндпоинты сервера. Как на них сделать запрос?

### Запросы на эндпоинты
Это HTTPS сервер, следовательно, нужно перейти в папку `certs` коневого каталога и использовать при обращении сертификат `cert.pem`.

#### Эндпоинты аккаунта
Сделаем запрос с помощью `cURL`:

##### Регистрация
Введите следующее:
```bash
curl --cacert cert.pem --location 'https://localhost:<port>/register' \
--header 'Content-Type: application/json' \
--data '{
"login":"cool_login",
"password":"q1w2e3"
}'
```
> **info**: вместо `port` введите порт, на котором вы подняли сервер.

Если вы ещё не регистрировали данный логин, вы получите сообщение об успехе создания аккаунта.

```json
{
    "message":"success to create account"
}
```

##### Вход
Для входа нужно обратиться к следующему эндпоинту:
```bash
curl --cacert cert.pem --location 'https://localhost:<port>/login' \
--header 'Content-Type: application/json' \
--data '{
"login":"cool_login",
"password":"q1w2e3"
}'
```
В случае успеха вы получите access и refresh токены
```json
{
    "access_token":"<token>",
    "refresh_token":"<token>"
}
```
В дальнейшем их необходимо использовать для отзыва токенов, обновления их и обращения к защищённым эндпоинтам.

##### Выход
Или по-другому отзыв токенов. Принимает в своём теле access токен.
```bash
curl --cacert cert.pem --location 'https://localhost:<port>/logout' \
--header 'Content-Type: application/json' \
--data '{
"access_token":"<token>"
}'
```
При успехе access токен станет невалидным.

##### Обновление токенов
Токены refresh и access будут обновлены. Введите следующее:
```bash
curl --cacert cert.pem --location 'https://localhost:<port>/refresh' \
--header 'Content-Type: application/json' \
--data '{
"refresh_token":"<token>"
}'
```

#### Защищённые эндпоинты
На них потребуется отправка access токена. Рассмотрим примеры.

##### Вычислительный эндпоинт
Отправьте следующее:
```bash
curl --cacert cert.pem --location 'https://localhost:<port>/api/v1/calculate' \
--header 'Content-Type: application/json' \
--header 'Authorization: <access_token>' \
--data '{
"expression":"<expression>"
}'
```

На этот эндпоинт мы отправляем выражение. Если оно валидное, нам придёт сообщение:
```json
{
    "task_id":"<uuid>"
}
```

ID нужно использовать тогда, когда мы захотим взять выражение из БД.

##### История вычислений
Чтобы её получить, введите:
```
curl --cacert cert.pem --location 'https://localhost:<port>/api/v1/expressions' \
--header 'Authorization: <access_token>'
```

Обратите внимание, тут используется GET метод.

После обращения, вы получите следующий ответ:
```json
{
    "expressions":
    [
         {
              "id":"<uuid>",
              "expression":"<expr>",
              "result":"<result>",
              "status":"<status>",
              "creating_time":"<time>"
         }
    ]
}
```

##### Конкретное выражение
Для получения конкретного выражения необходимо совершить запрос на следующий эндпоинт, указав при этом ID желаемого выражения:
```bash
curl --cacert cert.pem --location 'https://localhost:<port>/api/v1/expressions/<id>' \
--header 'Authorization: <access_token>'
```

Вы получите ответ вида:
```json
{
     "expression":
     {
          "id":"<uuid>",
          "expression":"<expr>",
          "result":"<result>",
          "status":"<status>",
          "creating_time":"<time>"
     }
}
```

### Возвращаемые коды
| Код | Значение |
| :-: | :------: |
| `200` | ОК |
| `201` | Создание успешно |
| `400` | Невалидный запрос |
| `401` | Авторизация провалена |
| `403` | Запрещённый метод |
| `404` | Эндпоинт не найден |
| `422` | Не удалось обработать запрос |
| `500` | Внутренняя ошибка сервера |
